# IQARG — API Contract

> **Version:** 0.1  
> **Status:** Initial MVP contract — implementation baseline  
> **Scope:** Local MVP v1 only

This document defines the application boundary between the React frontend and FastAPI backend. The frontend must not call ComfyUI or segmentation runtimes directly.

## 1. Contract rules

- Base URL: `http://localhost:8000/api/v1`
- JSON is used for request/response metadata unless stated otherwise.
- Image and mask files are transferred as binary or multipart form data.
- All IDs are opaque strings generated by the backend.
- All coordinates use the **original uploaded image's pixel coordinate system**.
- Coordinate origin is the top-left corner; `x` increases rightward and `y` increases downward.
- Pixel coordinates are zero-based. Valid coordinates satisfy `0 <= x < width` and `0 <= y < height`.
- The backend is authoritative for job state and file references.
- The original upload is immutable.
- Generation requires an explicitly approved mask.
- The API must never expose internal absolute filesystem paths.

## 2. Common response and error format

Successful JSON responses use the endpoint-specific schemas below.

Errors use this shape:

```json
{
  "error": {
    "code": "INVALID_IMAGE",
    "message": "The uploaded file is not a supported image.",
    "details": {}
  }
}
```

Use appropriate HTTP status codes:
- `400` malformed request or invalid state transition
- `404` unknown image, mask, or job ID
- `413` upload exceeds configured size limit
- `415` unsupported media type
- `422` valid JSON shape but invalid field values
- `500` unexpected application error
- `503` required model/service unavailable

Do not return stack traces, secrets, host paths, or raw provider internals to the client.

## 3. Image upload

### `POST /images`

Content type: `multipart/form-data`

Form fields:
- `file` — required image file

MVP initially supports common raster formats: PNG, JPEG, and WebP. The backend must validate actual decoded content, not trust the filename or browser MIME type.

Response `201 Created`:

```json
{
  "image_id": "img_01J...",
  "filename": "source.png",
  "content_type": "image/png",
  "width": 2048,
  "height": 1365,
  "preview_url": "/api/v1/images/img_01J.../content",
  "created_at": "2026-11-23T10:30:00Z"
}
```

### `GET /images/{image_id}`

Returns image metadata using the same fields as the upload response.

### `GET /images/{image_id}/content`

Returns the original image bytes with the correct content type. This endpoint must serve the immutable original upload.

## 4. Point-based segmentation

### `POST /images/{image_id}/segmentations`

Content type: `application/json`

Request:

```json
{
  "point": {
    "x": 820,
    "y": 510
  }
}
```

The point is expressed in original-image pixel coordinates. The backend validates that it lies within the image bounds.

Response `202 Accepted`:

```json
{
  "segmentation_id": "seg_01J...",
  "image_id": "img_01J...",
  "status": "processing"
}
```

Segmentation may take time. The frontend polls the segmentation resource until it is ready.

### `GET /segmentations/{segmentation_id}`

Processing response:

```json
{
  "segmentation_id": "seg_01J...",
  "image_id": "img_01J...",
  "status": "processing"
}
```

Completed response:

```json
{
  "segmentation_id": "seg_01J...",
  "image_id": "img_01J...",
  "status": "completed",
  "mask_id": "mask_01J...",
  "mask_preview_url": "/api/v1/masks/mask_01J.../content",
  "width": 2048,
  "height": 1365
}
```

Failed response:

```json
{
  "segmentation_id": "seg_01J...",
  "image_id": "img_01J...",
  "status": "failed",
  "error": {
    "code": "SEGMENTATION_FAILED",
    "message": "Could not produce a usable mask."
  }
}
```

The API contract intentionally does not expose Mirage, SAM 2, or another model's internal request format. The backend selects the configured segmentation adapter.

## 5. Mask retrieval, refinement, and approval

A mask is a single-channel image aligned exactly to the original image dimensions. For the initial contract, mask pixels are interpreted as:
- `0` = outside selected region
- `255` = inside selected region

Intermediate grayscale/soft-alpha masks may be used internally, but the API must document their interpretation before exposing them.

### `GET /masks/{mask_id}/content`

Returns the mask image bytes. The response includes the appropriate image content type.

### `POST /masks/{mask_id}/refinements`

Optional refinement operation. This endpoint is included for a simple first implementation of mask correction; detailed brush/eraser editing can be added later without changing the segmentation contract.

Request:

```json
{
  "operation": "dilate",
  "amount": 4
}
```

Allowed initial operations:
- `dilate`
- `erode`
- `feather`

`amount` is an integer pixel radius greater than or equal to zero, with a backend-configured maximum. `feather` may create grayscale alpha values.

Response `200 OK`:

```json
{
  "mask_id": "mask_01J...",
  "width": 2048,
  "height": 1365,
  "mask_preview_url": "/api/v1/masks/mask_01J.../content",
  "status": "candidate"
}
```

Refinement must not mutate the original candidate mask in place. The implementation may return a new mask ID if that is required to preserve version history; if so, return the new ID and document the parent relationship.

### `POST /masks/{mask_id}/approval`

Request:

```json
{
  "decision": "approve"
}
```

Allowed decisions: `approve`, `reject`.

Response:

```json
{
  "mask_id": "mask_01J...",
  "status": "approved"
}
```

A rejected mask cannot be used for generation. If the user wants to try another selection, create a new segmentation request.

## 6. Inpainting generation

### `POST /generations`

Content type: `application/json`

Request:

```json
{
  "image_id": "img_01J...",
  "mask_id": "mask_01J...",
  "prompt": "Replace the selected object with a small ceramic vase.",
  "negative_prompt": "",
  "settings": {
    "seed": null
  }
}
```

Rules:
- `image_id` and `mask_id` must refer to the same source image.
- The mask must be approved.
- `prompt` is required and must be non-empty after trimming.
- `negative_prompt` is optional.
- Only settings explicitly supported by the configured workflow may be accepted. Do not silently ignore unsupported settings.
- Model/workflow-specific parameters are not part of the frontend contract until benchmarked and approved.

Response `202 Accepted`:

```json
{
  "job_id": "job_01J...",
  "image_id": "img_01J...",
  "mask_id": "mask_01J...",
  "status": "queued",
  "progress": 0
}
```

### `GET /jobs/{job_id}`

Example response:

```json
{
  "job_id": "job_01J...",
  "image_id": "img_01J...",
  "mask_id": "mask_01J...",
  "status": "generating",
  "progress": 35,
  "message": "Generating image",
  "result_url": null,
  "error": null,
  "created_at": "2026-11-23T10:35:00Z",
  "updated_at": "2026-11-23T10:35:12Z"
}
```

Completed response:

```json
{
  "job_id": "job_01J...",
  "image_id": "img_01J...",
  "mask_id": "mask_01J...",
  "status": "completed",
  "progress": 100,
  "message": "Generation completed",
  "result_url": "/api/v1/jobs/job_01J.../result",
  "error": null,
  "created_at": "2026-11-23T10:35:00Z",
  "updated_at": "2026-11-23T10:36:10Z"
}
```

Failed response:

```json
{
  "job_id": "job_01J...",
  "image_id": "img_01J...",
  "mask_id": "mask_01J...",
  "status": "failed",
  "progress": 0,
  "message": "Generation failed",
  "result_url": null,
  "error": {
    "code": "GENERATION_SERVICE_UNAVAILABLE",
    "message": "The image generation service is unavailable."
  },
  "created_at": "2026-11-23T10:35:00Z",
  "updated_at": "2026-11-23T10:35:12Z"
}
```

### `GET /jobs/{job_id}/result`

Returns the generated, composited result image. It must not return an uncomposited provider output if that would violate the pixel-preservation requirement.

### `POST /jobs/{job_id}/decision`

Request:

```json
{
  "decision": "accept"
}
```

Allowed decisions: `accept`, `reject`.

Response:

```json
{
  "job_id": "job_01J...",
  "status": "accepted"
}
```

Only completed jobs can be accepted or rejected. Accepting a result records it as an accepted output; it does not modify the original upload.

### `POST /jobs/{job_id}/retry`

Request:

```json
{
  "prompt": "Replace the selected object with a blue ceramic vase.",
  "negative_prompt": ""
}
```

A retry creates a new generation job linked to the same image and approved mask. It must not overwrite the prior result or any accepted result.

Response `202 Accepted`:

```json
{
  "job_id": "job_01K...",
  "parent_job_id": "job_01J...",
  "status": "queued",
  "progress": 0
}
```

## 7. WebSocket progress

### `WS /ws/jobs/{job_id}`

The client connects after receiving a `job_id`.

Server messages:

```json
{
  "event": "job.progress",
  "job_id": "job_01J...",
  "status": "generating",
  "progress": 35,
  "message": "Generating image"
}
```

Completion:

```json
{
  "event": "job.completed",
  "job_id": "job_01J...",
  "status": "completed",
  "progress": 100,
  "result_url": "/api/v1/jobs/job_01J.../result"
}
```

Failure:

```json
{
  "event": "job.failed",
  "job_id": "job_01J...",
  "status": "failed",
  "error": {
    "code": "GENERATION_FAILED",
    "message": "Generation failed. You can retry the job."
  }
}
```

The WebSocket is a progress channel, not the source of truth. On reconnect, the frontend must call `GET /jobs/{job_id}` to retrieve the current state.

## 8. Job and resource states

### Segmentation states

- `processing`
- `completed`
- `failed`

### Mask states

- `candidate`
- `approved`
- `rejected`

### Generation job states

- `queued`
- `generating`
- `completed`
- `failed`
- `accepted`
- `rejected`

The backend validates all state transitions. Clients must not set state fields directly.

## 9. Pixel preservation requirement

The generation service may return an image that changes pixels outside the intended region. The application backend must perform final compositing against the immutable original using the approved final compositing mask.

The delivered result must satisfy:

- Original and generated result have the same dimensions.
- Pixels outside the final compositing mask are identical to the original.
- The original upload is never modified.
- The exact compositing mask used is retained with the job for reproducibility.

Automated tests must assert pixel equality outside the mask.

## 10. MVP implementation notes

- The routes above are the agreed application-level interface; internal ComfyUI routes are not exposed.
- Polling segmentation status is sufficient for MVP; a segmentation WebSocket is not required initially.
- Job progress uses WebSocket, with REST polling as recovery.
- The backend may initially use in-memory job metadata for development, but generated files and uploads must be stored persistently. The implementation must document that in-memory job metadata is lost on backend restart.
- Do not add a database, Redis, authentication, or cloud provider in MVP v1 without a separate approved decision.
- Set upload-size, image-dimension, and refinement-operation limits in backend configuration. Document the chosen values in the implementation README.
- Any change to routes, required fields, state names, coordinate conventions, or mask semantics requires updating this document and approval before implementation.
